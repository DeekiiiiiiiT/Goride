ROAM DOMINION — MAINTENANCE: "MAY NEED" ITEMS + SUPPLIES FULL DESIGN PROMPT (GOOGLE STITCH)




Roam Dominion - Maintenance templates · May need + Supplies (Desktop Admin, for the owner and catalog staff):

Design the screens that let the owner say which parts and shop supplies each maintenance job may need. They sit inside the existing "Maintenance templates" section of the Roam Dominion admin console, next to the Jobs tab, and must look like the same product. In this section a JOB is one piece of maintenance work you can log, e.g. "Throttle Body Cleaning" (a Service: only a cost is logged) or "Intake Manifold Gasket" (a Part: it goes onto the car and has a part number). A SUPPLY is something used up while doing the work and the same for every car, e.g. "Throttle body cleaner" (sold by the can), "Brake cleaner", "Thread locker". Each job gets a "MAY NEED" list of part types and supplies, each marked "Usually" or "Sometimes", with an optional usual quantity ("1 can") and a short note. When a mechanic logs that job in the Roam Fleet app, the list appears so they can tick what was actually used. "May need" is different from the existing "ALSO DO" list: Also do suggests separate work with its own line ("Throttle Body Relearn"); May need is stuff used up inside this one job. A part can't be in both lists for the same job. Nothing is ever deleted: supplies are retired and can be restored, and removing an item from a job hides it without erasing old logs. Dominion only feeds this list to the apps; it never shows fleet names, plates, prices, suppliers, stock or how often anything was used. Draw each screen at FULL HEIGHT so every element is visible; nothing may be cut off, blurred or hidden behind another layer except where a screen below says so.

BUTTON RULES (strict):
- Every action is a real button with a visible border or fill — never plain text, never underlined, never faint grey.
- Primary = solid blue. Secondary = visible border + dark text. Icon buttons = 32px with a visible border.
- Destructive buttons (Remove, Retire, Cancel) are red: red outline + red text; the final confirm in a dialog is solid red.
- One primary (blue) button per screen, drawer or panel.
- No browser pop-ups; every confirm is an in-app dialog.

DESIGN PRINCIPLES:
- Calm and exact, a well-kept service manual, not a spreadsheet
- Plain words first, codes small and muted
- No prices, suppliers, stock, fleet names, plates, usage counts from the apps, percentages, server/sync/version labels or made-up IDs
- Use only the real data listed under each screen
- Everything reachable by keyboard: reorder has Move up / Move down buttons as well as a drag handle; panels move focus in when they open and back to the button that opened them when they close

INTERACTIONS:
- "+ Add item" opens the Add item panel (Screen 3); "Add" closes it and the new row appears at the bottom of the May need list
- "Edit" on a May need row reopens the same panel with the item locked (only need, quantity and note can change)
- "Remove" removes the row straight away and shows a toast "Removed from May need. Old logs keep it." (add it again with "+ Add item" if needed)
- Move up / Move down and drag reorder the list; the order is the order Fleet shows
- "+ New supply" inside the panel opens Screen 5 (Add) and returns with the new supply selected
- "Retire" on a supply opens Screen 6 Frame A; "Restore" brings it back with its old May-need rows
- Esc closes panels and dialogs; focus returns to the button that opened them
