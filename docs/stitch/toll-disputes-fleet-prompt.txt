Roam Fleet - Disputes tab in Driver Settlements, and the Tolls tab in Fleet Policy Configuration (Desktop Web App, for the fleet owner and fleet manager):

Design screens for toll disputes in Roam Fleet. On a trip, the passenger always owes the toll, never the fleet. Uber pays the toll back to the driver; when Uber pays short (the Portmore toll costs J$390.00 and Uber paid back J$370.00), the driver asks Uber for the remaining J$20.00 from the Uber driver app within 9 days of the trip. Roam opens these disputes by itself. Area one is a new "Disputes" tab in Driver Settlements: the owner sees every open dispute of every driver (not sent yet, waiting on Uber, late) and can mark one as sent for a driver, close one as lost, or open the week the toll belongs to. Area two is a new "Tolls" tab in Fleet Policy Configuration: who pays when a dispute is lost or runs out of time, each platform's toll rules, and each toll plaza's price per platform with the date it starts. The person using this is not an accountant: every card says in plain words what it is for. The design must feel modern, calm and effortless, like the best business banking apps. Every screen is tall enough to show everything, with no inner scrolling. Draw only the screens asked for in this message.

DESIGN PRINCIPLES:
- Each screen answers "what needs me now?" first: counts and amounts at the top, then the list, most urgent first.
- The days left are always visible on a dispute that is not sent; they turn red with 2 days or fewer left.
- "Late" is a warning, not a loss. "Lost" is never the main button.
- Settings read like plain questions with plain answers ("When a dispute is lost, who pays?" — "The fleet" / "The driver"), never field names.
- Calm, not alarming: red only for late disputes and missing settings.
- One view per screen.

ADDITIONAL UI COMPONENTS:
- Summary tile, dispute row, driver filter chip, centered dialog: as in BRAND IDENTITY.
- Segmented control (two options) for "The fleet" / "The driver".
- Platform row: platform name, Yes/No switches, "How" dropdown (On each trip, In weekly adjustments, The rider pays the driver, Roam charges the rider, Not paid back), number box for days.
- Price table with a "Now" chip, a "Starts <date>" chip and a red "Missing" chip. Tag price is read-only (no command accepts a tag price yet).
- Side panel for one plaza's price history.
- Sticky footer bar with change count and Save.
- Reason text box with a live 8-character minimum.

INTERACTIONS:
- Data: Disputes tab reads public.toll_v2_disputes(p_driver) → active rows + byDriver (toSend, sent, late, leftMinor) for the chips and badge. Tolls tab reads public.toll_v2_toll_settings().
- Driver chips filter the list; tiles always count every driver.
- "Mark as sent" → dialog → mark_dispute_sent {dispute_id, expected_dispute_version}; only on to_send rows that are not windowClosed.
- "Lost" → dialog → close_dispute_lost; only on sent rows. A NEEDS_APPROVAL refusal opens the reason dialog and resends with self_approval_reason.
- "Open week" opens Week Reconciliation on chargeWeekKey, Tolls step, part 3.
- No "Refund received" here: refunds are linked on Week Reconciliation step 3 only.
- Tolls tab: any change shows the change count and enables Save; Save → reason dialog (settings always need it) → change_toll_settings (platform_settings.<platform>.<snake_case field>, dispute_policy.lost_bearer / expired_bearer). Leaving with unsaved changes asks in an in-app dialog.
- "Add rate" → plaza_rates_add [{plaza_id, platform, rate_minor, effective_from}]; never replaces old rates.
- The "missing" list is the server's `missing` (same list the matcher refuses on); each line's Add rate opens the dialog prefilled.
- Switches are shown read-only (no command changes them from this screen).
- Keyboard: Tab between buttons, Enter confirms dialogs, Escape closes them.
