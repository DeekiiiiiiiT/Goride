ROAM DOMINION — PENDING CATALOG · PARTS TO LOOK UP — FULL DESIGN PROMPT (GOOGLE STITCH)




Roam Dominion - Vehicle Database · Pending catalog (Desktop Admin, for the owner):

Design the changes to the existing "Pending catalog" page of Roam Dominion, the master parts database that feeds every Roam app. Pending catalog is the owner's to-do list of parts Roam doesn't have yet: each row is one part for one car version that needs to be looked up, checked against a trusted source and added to the database. Until now every row came from the Find parts screen. From now on rows also arrive automatically when a part that isn't in the database is logged in a service, so the page needs to show where a request came from ("Service log" or "Find parts"), the part number when one was given, and where on the car the part sits ("Front (before converter)", "Driver", "Low beam"). At the same time, the page stops showing how many fleets asked: Dominion is a database being built up over time and shows only its own data, never anything about the fleets that use it. Everything else on the page stays as it is today. The design must feel modern, calm and effortless: generous spacing, soft 12–16px rounded cards, soft shadows, larger type and clear hierarchy, like a modern consumer app rather than a technical tool. Draw each screen tall enough that every element is visible, with no inner scrolling and nothing cut off.

DESIGN PRINCIPLES:
- Dominion shows only the database: the car version, the part, its number, where it sits, and where the request came from. Nothing about who asked.
- One row = one part to look up for one car version; the same part asked again joins the same row.
- Show what's known, leave the rest empty: no part number shows as a muted dash, not an empty box.
- Add to the existing page, never take anything away, except the fleet count.
- Calm, not alarming: amber for waiting, red only for failures.
- Desktop-first (1440px), with a narrow layout. 8px spacing grid, soft shadows, skeleton loading.
- One view per screen.
