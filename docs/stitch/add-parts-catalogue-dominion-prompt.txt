Roam Dominion — Parts database, "Add parts → Parts from a catalogue page" (desktop admin console for the owner and catalog editors, who are not mechanics):

Design a complete, modern, high-fidelity redesign of the flow that records parts from a catalogue page. The real job: the owner has a catalogue site open (for example Toyota's own catalogue on Partsouq) showing a diagram and a list of part numbers for one car. They need to get every part on that page into the database, for the cars the page covers, with the right name and the right place (front sensor, rear sensor). A first-time user must finish it alone, with no one to ask: the screen itself says where to find the part number, which years the page covers, and why a name reads "Front oxygen sensor". Make each screen tall enough to show everything — no inner scrolling anywhere, no cut-off boxes. Draw only the screens asked for in this message. Dominion is the master reference database: no fleet names or plates, and no prices, suppliers, stock or quantities anywhere.

INTERACTIONS AND DATA (for the builder, not Stitch)
- Paste or type the link → read it at once (`GET …/parts/add/link-hints?url=`): returns the site, whether it is trusted, the maker, the frame codes. Fill every answer that came back; show a Change on each.
- Change maker → call the same link-hints route with the extra `maker` value and re-render the Site row's pill and its reason, in place. No page reload. Nothing typed is lost.
- Trust this site (owner only) → dialog → `POST …/catalog-research/trusted-sites` with domain, maker, kind → on success re-read the link and close; the Site row becomes Verified. A non-owner sees the amber note without the button, plus the line "Ask the owner to trust this site" and can carry on as Needs checking.
- Years this page covers → pre-tick only versions whose frame code matches AND whose catalogue years overlap the entered years; every other version stays visible and unticked with the amber "not on this page" pill. With no years entered, nothing is ticked.
- Selected cars save with the page's years by default; the crew can edit them per car; editing years never changes trust.
- Part type picked → the place buttons switch to that type's places (Front / Rear, corners, left/right, No.1–No.3) and the "Saves as" name updates ("Front oxygen sensor").
- Place buttons for catalyst parts read "Front (before converter)" / "Rear (after converter)" with the catalogue's own names on the muted line under them. Every screen prints place labels through one shared helper — never a raw code.
- Part number typed → look it up as you type; "Already on file as 'Front oxygen sensor' (4 cars). We'll add these cars to it." when found.
- Next on the parts step → blocked until every card has a type, a 4+ character number and a place where the type has one; the message names the card ("Part 2 needs a place."). A number repeated on the page is blocked with both row numbers.
- Save → one `POST …/parts/add/catalog-page` for the whole page; the answer carries the saved names (`savedNames`), which the Saved screen shows. On failure nothing is saved, every card stays, the red panel appears with "Try again".
- Undo (Saved, or Recently added) → in-app dialog, then `POST …/parts/undo` with the batch id; the whole batch (parts and fits) is removed.
- Phone 390px: one column everywhere; the step strip collapses to "Step 3 of 4 · Parts"; the parts cards stack; the save bar sits at the bottom above the safe area; the type list opens full width; no horizontal scrolling anywhere.
