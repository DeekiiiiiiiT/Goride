==================== FIRST PASTE ====================

Roam Dominion - Research Engine, "Add from a saved page" (desktop admin console for the owner, who is not a mechanic):

Design high-fidelity, modern screens for a new way to add parts to a car in the Roam Dominion admin console. Today the owner adds a part with a step-by-step "browser check": they open a catalogue website, look at the page and answer Roam's questions one number at a time. The new way is faster. The owner opens the car's page on any catalogue website, presses Ctrl+S to save it, and uploads that one file. Roam reads every part on the page, checks each number, side and date against the page's own text, and saves the parts that pass by itself. Only the rows that fail a check come back to the owner, each with a one-line reason and one button to fix it. It must feel effortless and trustworthy, like a premium consumer app: upload, a short calm wait, then a clear result. The wording must fit every catalogue website. Never name one site's layout, columns or section titles. Make each screen tall enough to show everything, with no inner scrolling and no cut-off boxes. Draw only the screens asked for in this message. Dominion is the master reference database: no fleet names, plates, prices, suppliers, stock or quantities anywhere.

INTERACTIONS
- Read page → `POST /admin/catalog-research/saved-pages` (multipart: file, vehicleCatalogId, jobId?, url?, again?) → result row (R1).
- Coverage "Saved pages read" → `GET /admin/catalog-research/saved-pages?vehicleCatalogId=` (R10); a row opens Screen 6/7 for that upload.
- Same file again → server returns the earlier row → Screen 8; "Read again" sends again=true (R9).
- Check this part → opens ResearchJobDrawer for that job (D3 / SP-26 made it a browser check).
- Done → closes, refreshes coverage and readiness.
- Error codes → Screen 9 cards: wrong_car, untrusted_site, cap_reached, too_big, not_web_page, no_rows.
- Overlays are in-app; Esc and Cancel close; no browser pop-ups.
