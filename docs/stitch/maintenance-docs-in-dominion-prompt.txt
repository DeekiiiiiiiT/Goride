==================== FIRST PASTE ====================

Roam Dominion - Maintenance templates: car documents in, values out (desktop admin console for the owner, who is not a mechanic):

Design high-fidelity, modern screens that make adding a car document effortless. The owner drops in a PDF (a car maker's maintenance sheet, a maintenance booklet, or an owner's manual). Roam reads its first pages by itself and fills in everything: which car it is for, which country, what kind of document it is, its name, the date printed on it, and which pages matter. The owner only checks and presses Upload. A service schedule document gives the part schedules (how often each part is changed). An owner's manual gives the car's specs: oil and fluids with their capacities, tyre sizes and pressures, the battery size, and every bulb. On the check screen each spec shows what Roam has now next to what the manual says, so nothing is ever changed without being seen, and the owner ticks which versions of the car each value is for (2WD, 4WD, turbo). It must feel effortless and premium, like a modern document app: big clear page pictures, calm progress, one obvious next step. Make each screen tall enough to show everything, with no inner scrolling and no cut-off boxes. Draw only the screens asked for in this message. Dominion is the master reference database: no fleet names, plates, drivers, vehicle counts, "used by", prices or stock anywhere.

ADDITIONAL UI COMPONENTS:
- FoundField: value + certainty (sure → green check + "From page N"; unsure → amber border + "Check this" + reason line). Used for doc type, make/model/years/version, country, name, printed date, pages.
- DocTypeChoice: two cards, schedule | owners_manual (maintenance_manual.doc_type).
- PageChips: editable list of pages/ranges in PRINTED numbers; stored as PDF pages in maintenance_manual.pages with page_offset (printed = PDF − offset). "Front memo page" = a page with no printed number (show its label, not a number).
- NowToManual: current catalogue value vs manual value; "Matches" when equal.
- VersionTicks: the family's catalogue versions in plain words (years · drive · engine), pre-ticked from the spec's "applies to" note.
- SpecCard sections: Fluids (oil grade, oil capacity with/without filter, coolant type/capacity, CVT fluid, transfer, differential, washer, fuel grade + tank), Tyres (vehicle_tyre rows), Battery, Bulbs (vehicle_bulb rows).
- Exact colours (text-[#…]), never Tailwind colour names (Dominion dark mode remaps them).

INTERACTIONS:
- S1 choose/drop → the browser reads the text layer of pages 1–15 + contents with pdf.js (cMaps on) → POST maintenance-manuals/identify {text, page_count, file_name} → DeepSeek returns make, model, printed date, market, doc_type, title, page_offset, suggested pages with reasons → catalogue match (make/model; years from printed date against production years) → S2/S3. No text layer → send first 6 page images → S7 with gaps.
- Years from a printed date pick the catalogue years that contain that date (June 2021 → 2020–). The owner can change them; a dated document never silently covers earlier years (DOC-05).
- Upload as today (upload-url → PUT → uploaded) with doc_type, pages, page_offset, year_from/year_to.
- owners_manual pages go to the specs reader (DOC-06) and also return any intervals they print (tyre rotation 5,000 km, cabin filter 20,000 / 10,000).
- S5 Approve writes to the ticked versions only: vehicle_catalog columns (oil, coolant, tank), catalog_spec_value (new spec keys, trust_route 'maker_document'), vehicle_tyre, vehicle_bulb; each change writes a history line (who, when, old, new, manual, printed page) (DOC-12). "Approve all" skips rows with an amber note.
- S6 is read-only, shown on the existing catalogue car page; the page button opens the page picture.
- Owner-only: Approve, Approve all, Reject. Staff can upload and edit.
