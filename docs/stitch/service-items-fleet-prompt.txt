ROAM FLEET — LOG SERVICE: "ITEMS USED" + FINISH SAVING FULL DESIGN PROMPT (GOOGLE STITCH)




Roam Fleet - Log service · Items used (Desktop Web App, for fleet managers and their staff):

Design the screens that let a fleet manager record the parts and supplies a job used up, right inside the existing "Log service" dialog of Fleet maintenance in the Roam Fleet app, plus the service-history screens that go with it. Today, when someone ticks "Throttle Body Cleaning" they can only type one cost. Now each job can come with a short "Items used" list that Roam has prepared (for Throttle Body Cleaning: "Throttle body cleaner", usually 1 can, and "Throttle Body Gasket", sometimes). Nothing is ever ticked for them: they tick what was actually used, say how many and what each cost (or leave the cost blank if they don't know), and it is saved with the job and added to the bill. They can also add something that isn't on the list with "+ Other item". The same dialog keeps its four steps: 1 Date & mileage, 2 Work done, 3 Details, 4 Review. The person using it is a normal fleet owner, not a mechanic: plain words, no codes, no part-number jargon unless they choose to type one. Two new history states are also needed: a service that didn't finish saving (with a "Finish saving" button), and the message shown when someone else changed a service while it was open. Draw each screen at FULL HEIGHT so every element is visible; nothing may be cut off, blurred or hidden behind another layer except where a screen below says so.

  - footer: red "Cancel" button on the left, outline "← Back", and the black primary button on the right

  - Primary: Near-black (#030213) — primary buttons, the active step, selected choices

BUTTON RULES (strict):
- Every action is a real button with a visible border or fill — never plain text, never underlined, never faint grey.
- Primary = solid black. Secondary = visible border + dark text. Icon buttons = 32px with a visible border.
- Cancel, Remove and Discard are red: red outline + red text (the dialog's "Cancel" is solid red as it is today).
- One primary button per screen.
- No browser pop-ups; every message and confirm is in-app.

DESIGN PRINCIPLES:
- Desktop-first (1440px), with a phone version
- Plain words for a normal person: "Items used", "Cost each", "Leave blank if you don't know" — never "consumables", "SKU", "line item" or codes
- Never tick anything for the user; suggestions are just suggestions
- The money adds up in front of them: every item shows its amount, every job shows "Job J$ X + items J$ Y"
- Capture, never block: a blank cost is fine, it simply isn't added
- One save: the save button shows a spinner and can't be pressed twice
- 8px spacing grid, hairline borders, soft shadows, skeleton loading

- "Finish saving" retries the save for a not-finished service; it never makes a second service
- "Reload" on Screen 7 reloads the service with the latest changes; "Cancel" closes without saving
- Esc closes panels; focus returns to the button that opened them; every checkbox, stepper and button works by keyboard
