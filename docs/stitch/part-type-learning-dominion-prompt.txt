==================== FIRST PASTE ====================

Roam Dominion - New part types from a saved page (desktop admin console for the owner, who is not a mechanic):

Design high-fidelity, modern screens for a "self-learning" parts database in the Roam Dominion admin console. Today the owner uploads a page they saved from a car-parts catalogue website, and Roam saves every part on it that matches one of Roam's part types (air filter, brake pads, shock absorber…). Parts Roam has no type for yet — an air cleaner hose, a ventilation pipe — are just listed as "not a Roam part type" and thrown away. Now Roam turns them into suggestions: for each part it doesn't know, it suggests a plain name and a part group, and the owner presses one button, "Add part type". Roam creates the part type, saves those parts from the same page with their own dates, and makes a picture of each — no second upload. Small fixings (clips, clamps, bolts) are never suggested. If Roam already has a type that covers the part, the card says so and saves the parts under it instead. It must feel effortless and trustworthy, like a premium consumer app: clear cards, one obvious button each, calm states. Make each screen tall enough to show everything, with no inner scrolling and no cut-off boxes. Draw only the screens asked for in this message. Dominion is the master reference database: no fleet names, plates, drivers, vehicle counts, "used by", prices, suppliers, stock or quantities anywhere.

ADDITIONAL UI COMPONENTS:
- SuggestionCard (plan S1): name box (max 60), page's words (mono, grey), Part group dropdown (13 groups; Fluids + Tires & wheels tagged "no picture"), rows panel (count, numbers, periods), buttons. Owner-only buttons; staff see them disabled with "Only the owner can add a part type".
- FixingsLine: bolt icon + "{n} fixings ({names}) — Roam doesn't track these". Never a card, never a button.
- GroupPicker: the 13 groups, required, no default on the Part types screen; pre-set to the suggestion on a card.
- HiddenList row: page's words (mono), who + when, "Suggest again" (owner). Loading = two grey placeholder rows.

INTERACTIONS:
- "Add part type" → POST saved-pages/:id/part-type (plan R5) with name + group; card goes Adding… → Added (or Added, needs you / Couldn't add). The top count pills recount; the pictures line updates as pictures are queued.
- "Save under {type}" → same route with the existing type; no type is created.
- "Not a part we track" → dismissal (D3); card disappears, its rows stay listed with no button; it shows up in "Hidden from saved pages".
- "Suggest again" removes the dismissal; the phrase can be suggested on the next upload.
- "Check this part" opens the normal browser check, as in the "Needs you" group today.
- Pressing Add twice on the same card makes one type (rule 6).
