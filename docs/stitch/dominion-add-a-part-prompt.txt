Roam Dominion - Parts database, "Add a part" (Desktop Admin, for the owner and catalog editors — non-mechanics and mechanics alike):

Design high-fidelity desktop screens for a guided, self-serve way to add ANY part to the Parts database in the Roam Dominion admin console — brake pads, oil filters, spark plugs, shocks, bulbs, wiper blades, batteries, fluids, tires and every other part type. Today, adding one part means three separate CSV uploads that must go in a set order, with database words a non-mechanic can't follow. The new flow matches the real-world task: "I found a part on a catalogue page". The editor answers four short questions — what is the part, how does it fit (which cars, which engine, or which size), does it replace a factory number, and where did you see it — reviews one plain sentence and saves. The app does the ordering and the matching behind the scenes. The old CSV import stays as "Bulk upload (advanced)". Dominion is the master reference database: it never shows fleet names or plates. Parts are information only: no prices, suppliers, stock or quantities anywhere.

The feel: modern, calm, uncluttered — one question per screen, generous white space, one primary action. Plain words first, with the trade term shown small and muted beside it (e.g. "Factory number · OE", "Fits by engine · Engine code"), so a beginner can follow and a mechanic still sees the precise term. Never dumbed down, never jargon-first.

DESIGN PRINCIPLES:
- Desktop-first (1440px wide); content column max 880px centred, so screens feel light
- One real-world task: "I found a part on a catalogue page". The user never chooses a template or an upload order.
- Four steps with a slim stepper: "1 The part · 2 How it fits · 3 Replaces (optional) · 4 Review". Done steps get a tick; the current step is filled primary.
- One question per screen. Each screen opens with one plain sentence and a tiny real example (e.g. "Like: oil filter 04152-40060 fits every 1KR-FE engine").
- Plain word first, trade term second, small and muted: "Factory number · OE", "Fits by engine · Engine code", "Size or spec · e.g. H4, 0W-20".
- The part type decides the defaults (how it fits, position choices, the spec fields, the hint). The user only changes what's different.
- The source page is asked in Step 1 and decides the trust chip, shown before saving with a one-line reason.
- The app shows what will happen automatically ("22 car versions have engine 1KR-FE", "3 more cars carry factory number 04465-B1190") so the user understands the matching without learning it.
- Help is one click away: "What do these words mean?" opens a side panel with the four ideas and one example each.
- Nothing is saved until "Save part"; every save can be undone from "Recently added".

INTERACTIONS:
- "+ Add a part" and "Start →" open Step 1; picking a part type sets the default "How it fits", the position chips, the spec fields and the hint
- The "How it fits" switch can be changed; switching keeps what's still relevant and clears the rest
- Typing an existing brand + number shows "Part already exists" at once; "Add more cars to it" jumps to Step 2 with the part loaded
- Choosing the source type updates the trust chip and reason immediately
- Ticking cars, choosing an engine or typing a size updates the live preview count as you go
- Step 3 is skipped automatically for "By size or spec"
- "Edit" on Review returns to that step with everything kept
- "Cancel" asks "Leave without saving? Nothing has been added yet." with "Keep editing" / "Leave"; leaving clears everything
- "Save part" shows a short progress bar on the button, then Saved
- "Undo" asks "Remove this part and its fits?" with "Cancel" / destructive "Remove"
- Hover: rows highlight in the primary container colour; focus rings 2px primary; every input has a visible label
